# 로드맵: 재방문 장치와 정책 정보

작성일: 2026-10-15. 현재 코드(정적 GitHub Pages, 로그인 없음, 관심 목록은 localStorage, 해시 라우팅, 방문 분석 없음)를 기준으로 한 작업 계획이다. 기간은 순서를 정하기 위한 대략치이며 확정 견적이 아니다.

## 원칙

- 서버를 새로 두지 않는다. 매일 빌드(GitHub Actions)와 정적 파일로 할 수 있는 것부터 한다.
- 로그인 없이 쓰는 구조를 유지한다. 개인 데이터는 브라우저에 두고, 수집하는 정보는 최소화한다.
- 재방문 장치는 실제로 관측된 변화(새 거래, 신고가, 국면 변화, 새 정책)부터 알린다. "급등 알림" 같은 자극적인 장치는 만들지 않는다. 예측은 지금처럼 실험 표시와 검증 기준을 유지한다.
- 정책은 날짜와 원문만 보여 주고 "정책 때문에 올랐다/내렸다" 같은 인과 해석은 하지 않는다.

## 현재 빈틈

1. 방문 분석이 없어서 재방문율과 개선 효과를 알 수 없다.
2. 관심단지의 새 거래 표시는 사이트를 열어야만 보인다. 사이트 밖에서 알리는 수단이 없다.
3. 관심 목록이 브라우저에만 있어서 저장소를 지우거나 기기를 바꾸면 사라진다.
4. 해시 라우팅이라 지역·단지 페이지가 검색에 따로 노출되지 않고, 공유 미리보기도 모든 페이지가 같다.
5. 새 거래 판정 기준(`seen`)이 마지막 **계약일**이라서, 계약은 그 전에 했지만 늦게 신고된 거래가 새 거래에서 빠진다 (`public/app.js`의 관심단지 화면).

## 세부 사항

### 1. 방문 분석

- 볼 지표: 7일·30일 재방문율, 관심단지 1개 이상 등록 비율, 화면 종류별 조회(개요/지역/단지/관심단지).
- 브라우저 단위라 기기 변경·저장소 삭제에 따른 오차가 있다. 트래픽이 적은 동안은 수치만으로 결론 내리지 않는다.

### 3. 정책 자료 형식

```json
{
  "id": "2026-xx-loan",
  "announced": "2026-xx-xx",
  "effective": "2026-xx-xx",
  "ended": null,
  "title": "…",
  "category": "대출 | 규제지역 | 토지거래허가 | 세제 | 공급",
  "regions": ["all"],
  "summary": "한두 줄 요약",
  "source": "정책브리핑·국토부·금융위 보도자료 URL"
}
```

- 발표일과 시행일을 구분한다. 차트 마커는 발표일 기준으로 표시한다.
- 해제·변경된 정책은 지우지 않고 `ended`를 채워 이력으로 남긴다.
- 페이지에 "요약은 참고용, 정확한 조건은 원문 확인" 안내와 마지막 수정일을 표시한다.
- 새 정책 후보는 정책브리핑·보도자료 RSS로 모을 수 있지만, 사람이 확인한 뒤 PR로 추가한다.
- 초기 내용: 최근 3~5년 주요 정책 초안을 공식 출처 기준으로 만들고 날짜·대상 지역을 검토한다.

### 4. 새 거래 판정 보완 (선행 과제)

- 브라우저의 계약일 비교 대신, 빌드에서 이전 배포 대비 새로 들어온 거래를 계산한다. 화면에는 신고일이 아니라 "새로 확인된 거래"로 표시한다.
- 매매 자료에 거래 고유번호가 없으므로 단지·계약일·면적·층·금액으로 비교하고, 조건이 같은 실제 복수 거래는 개수로 보존한다.
- 처음 이력을 만들 때 기존 거래 전체를 새 거래로 표시하지 않는다.
- 취소·정정은 정확히 연결할 근거가 없으면 추가·삭제로만 표시한다.

### 6. 외부 채널

- 텔레그램 봇 토큰은 저장소 Secrets에 두고, 토큰이 없으면 게시 단계만 건너뛴다(기존 ECOS·REB 키와 같은 방식).
- 웹 푸시는 iOS에서는 홈 화면 추가 시에만 동작하고 발송 서버가 필요하므로, 측정 결과를 보고 따로 판단한다.

## 후순위

전국 확대, 커뮤니티, 예측 모델 추가, 유료화, 계정 동기화는 관심 등록과 반복 확인이 검증된 뒤 판단한다.
